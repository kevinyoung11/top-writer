# 右侧语音入口与移动端适配设计

## 目标

让 Top Writer 的语音副驾不再持续占用编辑器右侧宽度。用户通过既有右侧纵向工具栏中的语音入口按需打开它；在窄屏上，语音副驾以底部抽屉呈现，正文始终优先。

## 交互

- 右侧纵向工具栏新增具名“语音副驾”按钮，具备 `aria-expanded` 与 `aria-controls`。
- 宽度大于等于 1100px 时，点击按钮打开独立滚动的右侧抽屉；关闭后编辑器恢复完整可用宽度。
- 宽度为 700–1099px 时，抽屉固定在右侧并覆盖在内容之上，不改变编辑器栅格列。
- 宽度小于 700px 时，同一入口打开底部抽屉；抽屉不遮挡底部朗读控制条，并支持关闭按钮、Escape 和背景点击关闭。
- 语音副驾的文字指令、隐私确认、候选澄清、预览和撤回逻辑保持不变；入口只控制可见性，不参与语音领域决策。

## 布局与可访问性

- 移动端编辑器使用 16px 水平内边距；页面禁止横向溢出。
- 语音入口和抽屉关闭按钮的触控目标至少 44px。
- 打开后焦点移动到副驾标题；关闭后返回语音入口。
- 抽屉以原生按钮和语义区域构成；页面保留 `prefers-reduced-motion` 支持。
- 朗读播放器固定在编辑区底部，编辑区预留等高底部空间。

## 边界与验收

- 仅根布局组件负责入口、抽屉状态和断点；`VoiceCopilotPanel` 继续只是展示/输入层。
- 不改变控制器、编辑器桥、模型服务或偏好数据格式。
- 单元测试验证入口、打开/关闭、焦点返回和各断点 CSS 契约。
- Chromium E2E 验证移动视口下抽屉可打开、文字指令仍可访问、正文没有横向溢出。
